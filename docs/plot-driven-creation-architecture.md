# 剧情主线驱动架构（新草案）

## 1. 核心判断

创作页不应该再以“故事圣经字段”作为主入口。

更合理的主入口应该是：

- 先确定结构骨架
- 再组织剧情卡
- 再由剧情卡沉淀角色、关系、时间线、规则、伏笔
- 最后从锁定剧情卡展开成场

也就是说，系统的主链要改成：

- 幕
- 剧情卡
- 场

而不是：

- 角色
- 关系
- 时间线
- 规则
- 伏笔

这些仍然重要，但它们更适合作为“结果层”和“影响层”，而不是创作的第一入口。

## 2. 第一版主结构

第一版建议采用：

- 结构模板
- 幕
- 必要节点
- 剧情卡
- 场景卡
- 锁定层

这几层的关系是：

1. 用户先选结构模板，例如三幕剧、四幕剧、自定义。
2. 系统据此生成幕和必要节点。
3. 用户把剧情卡拖入对应的幕和节点。
4. 剧情卡被确认后，才沉淀为角色变化、关系变化、时间变化、规则变化、伏笔变化。
5. 锁定后的剧情卡再拆成场景卡，进入剧本开发。

## 3. 为什么“幕”必须先被确定

幕是最大的节奏容器。

编剧在长文本里真正需要先掌握的，不是某个角色字段，而是：

- 这一段故事在整体里属于哪里
- 它承担什么功能
- 它是否已经完成该幕的任务

所以第一版应该允许用户先选：

- 三幕剧
- 四幕剧
- 自定义幕数

系统据此自动生成：

- 幕列表
- 每幕目标
- 每幕容量提示
- 每幕必要节点

## 4. 节拍模板的正确位置

三幕剧、四幕剧是骨架。

Save the Cat、英雄之旅、Story Circle 这类，不应该直接替代骨架，而应该作为“节奏覆层”。

所以系统应该拆成两类模板：

- 结构模板：三幕、四幕、自定义
- 节奏模板：Save the Cat、英雄之旅、Story Circle、自定义

它们的关系是：

1. 结构模板决定幕怎么分。
2. 节奏模板决定必要节点和节拍提醒怎么落。
3. 用户可以选择只用结构模板，不套节奏模板。
4. 用户也可以在三幕结构下叠加 Save the Cat 的节点控制。

## 5. 剧情卡才是创作主对象

所有创作中的想法，都应该先变成剧情卡。

每张剧情卡至少应该包含：

- 卡片标题
- 一句话内容
- 所属幕
- 所属必要节点
- 剧情类型
- 当前状态
- 戏剧功能
- 前置依赖
- 后续影响
- 关联角色
- 关联关系
- 关联时间变化
- 关联规则变化
- 关联伏笔
- 是否进入锁定层

### 剧情类型建议

比“基本剧情、扩展剧情、可选剧情”更准确的叫法建议是：

- 主线剧情
- 强化剧情
- 备选剧情

原因：

- “主线剧情”表示不成立则故事不成立。
- “强化剧情”表示它增强人物、主题、节奏、情绪或悬念。
- “备选剧情”表示先保留，不立即进入主链。

### 剧情状态建议

- 草拟
- 推演中
- 待锁定
- 已锁定
- 已废弃

## 6. 场景卡在剧情卡之后

第一版建议采用：

- 幕 -> 剧情卡 -> 场景卡

而不是一开始就做：

- 幕 -> 场 -> 镜头

原因很简单：

1. 编剧阶段最核心的是剧情推进，不是镜头组织。
2. 镜头层更接近导演和分镜阶段。
3. 太早进入镜头，会显著拖慢创作速度。

所以镜头层建议放到后续版本：

- V1：幕 -> 剧情卡 -> 场
- V2：场 -> 段落动作 -> 镜头提示

## 7. 角色不是从属变量，而是一级对象

这一点非常关键。

角色不能只是剧情卡的附属字段，因为真实创作中常常出现三种情况：

1. 先有人物，再找剧情。
2. 先有剧情，再补人物。
3. 人物被调整后，反过来改掉剧情。

所以角色必须是一级对象，而且要与剧情卡双向关联。

### 角色层建议单独存在

角色层不再是旧式“故事圣经字段页”，而应成为：

- 角色卡
- 角色弧光轨迹
- 角色与剧情卡关系图

### 每个角色卡至少应包含

- 角色名
- 功能定位
- 外部欲望
- 内部需求
- 缺陷
- 核心伤口
- 核心秘密
- 角色当前立场
- 角色弧光起点
- 角色弧光终点
- 关联的主线剧情卡
- 关联的强化剧情卡
- 受其变化影响的剧情卡

### 角色与剧情的联动原则

当角色变化时，系统应主动标记受影响剧情卡。

例如：

- 改了主角的欲望
- 改了对手的动机
- 改了某段关系的性质

系统就应该提示：

- 哪些剧情卡会失效
- 哪些节点需要重写
- 哪些场景目标可能不成立

## 8. 类型片必须进入主控层

类型片不是一个标签而已。

它会直接影响：

- 节奏
- 必要节点
- 观众期待
- 信息揭示方式
- 角色功能配置
- 可接受的桥段类型

所以类型片也应该是一级控制层。

### 类型层建议包含

- 主类型
- 副类型
- 调性
- 观众承诺
- 必要桥段
- 可选桥段
- 禁忌项
- 节奏偏好

### 例如

悬疑片会影响：

- 线索投放
- 误导结构
- 真相揭示节点
- 信息密度

爱情片会影响：

- 情感靠近与拉远
- 误解与修复
- 关系转折点

成长片会影响：

- 弧光推进
- 价值观冲突
- 旧我到新我的关键转化

所以“类型层”必须能对剧情卡和结构层发出约束。

## 9. 锁定层是什么

锁定层不是新的写作层，而是确认层。

凡是进入锁定层的内容，都意味着：

- 进入正式故事圣经
- 进入正式时间线
- 进入正式关系网
- 进入正式伏笔追踪
- 进入正式场景开发

也就是说，锁定层负责把“想法”变成“系统事实”。

## 10. 页面应该怎么改

创作页建议重构为以下结构：

### 页面 1：结构页

用户在这里：

- 选择三幕 / 四幕 / 自定义
- 选择节奏模板
- 查看自动生成的幕和必要节点

### 页面 2：剧情板

用户在这里：

- 用便利贴式剧情卡组织主线、强化、备选内容
- 把剧情卡拖入对应幕和节点
- 查看前后依赖
- 决定哪些剧情卡进入锁定

### 页面 3：角色台

用户在这里：

- 建立角色卡
- 查看角色弧光
- 查看角色影响到哪些剧情卡
- 反向调整剧情

### 页面 4：类型约束页

用户在这里：

- 选择主类型和副类型
- 设定类型承诺
- 查看缺失桥段或节奏风险

### 页面 5：锁定层

用户在这里：

- 审核已锁定剧情卡
- 查看角色、关系、时间线、规则、伏笔的正式沉淀结果

### 页面 6：场景页

用户在这里：

- 把锁定剧情卡拆成场
- 排顺序
- 衔接因果

## 11. 最适合的交互方式

最适合这个系统的不是纯表单，也不是完全自由白板。

第一版最适合的是：

- 有轨道的便利贴工作台

具体形式：

- 顶部横向是幕
- 幕下是必要节点
- 节点下挂剧情卡
- 剧情卡可拖动
- 右侧显示这张卡影响的角色、关系、时间、规则、伏笔
- 点“锁定”后，写入锁定层

这样既有创作自由度，也不会失控。

## 12. 第一版联动规则

系统应至少支持这些联动：

### 结构变化

当用户把三幕改成四幕时：

- 重新计算幕
- 重新分配必要节点
- 标记受影响剧情卡

### 剧情卡变化

当用户移动、删除、锁定某张剧情卡时：

- 更新前后依赖
- 更新角色关联
- 更新时间线
- 更新伏笔状态

### 角色变化

当用户修改角色欲望、动机、弧光时：

- 标记相关剧情卡
- 标记相关场景卡
- 标记可能失效的关系变化

### 类型变化

当用户改主类型或副类型时：

- 重算必要节点
- 重算缺失桥段
- 重算节奏风险

## 13. 第一版最稳范围

如果按这个新方向推进，第一版最稳的范围建议是：

- 三幕 / 四幕模板
- Save the Cat 节拍覆层
- 幕 -> 剧情卡 -> 场景卡
- 角色作为一级对象
- 类型片约束层
- 锁定层沉淀
- 联动提醒

先不要做：

- 镜头级编排
- 分镜
- 导演调度
- 复杂制作管理

## 14. 下一步建议

下一轮最值得直接落地的是三件事：

1. 新的数据结构：幕、节点、剧情卡、角色卡、类型约束卡、场景卡。
2. 新的创作页信息架构：结构页、剧情板、角色台、类型约束页、锁定层、场景页。
3. 联动规则：改一个主线节点后，系统如何标记受影响内容。

这三件一旦定下来，后面的页面和数据库就可以稳定推进。
