# “原点编剧系统 V2.0”参考分析

## 1. 先说结论

这份参考稿不是简单的提示词堆砌，它已经有了比较成熟的系统意识。

它最有价值的地方，不在于那些具体句子，而在于四层设计：

1. 先锁“意图锚点”，再开始创作。
2. 把 AI 拆成多个专家，而不是一个万能角色。
3. 默认做顾问，不默认代写。
4. 有全局扫描和永久更新机制。

这四点和我们现在正在收敛的“最稳路线”高度兼容，应该吸收。

## 2. 这套参考稿最强的地方

### 强点 1：有“唯一真相”的概念

它把故事核、主题、主人公、弧光、视觉母题、类型这些内容放到一层最高约束里。

这非常重要，因为长对话系统最怕的不是写不出来，而是越写越偏。

### 强点 2：角色分工很清楚

它不是空泛地说“AI 帮你写”，而是把帮助拆成了：

- 结构
- 场景
- 对白
- 潜台词
- 视觉母题
- 情感弧光
- 节奏
- 心理动机
- 全局一致性

这很接近真实的剧本开发维度。

### 强点 3：强调可控性

它明确反对“幻觉式”和“千篇一律”的输出，这个方向是对的。

真正有价值的创作系统，不应该一上来就大段代写，而应该先给可判断、可选择、可追踪的方案。

### 强点 4：有锚点更新和沙盒模式

这两个设计说明它已经意识到：

- 创作不是一开始就定死
- 但修改也不能悄悄发生

这比很多纯聊天式写作工具成熟得多。

## 4. 它有哪些地方不能原样照搬

### 不能照搬 1：靠长初始化提示词驱动

这在手工对话里可用，但做应用会有几个问题：

- 用户负担太重
- 容易复制错误
- 系统状态难版本化
- 无法可靠追踪对象关系

所以它的“思想”要保留，但“用户自己复制整段提示词”的方式不应该保留。

### 不能照搬 2：完全禁止主动生成

这个原则适合防失控，但做应用时不能太绝对。

更合理的做法是：

- 默认顾问模式
- 用户明确要求时可以整合或扩写
- 所有扩写仍然受锚点和故事圣经约束

### 不能照搬 3：把约束只放在对话里

如果锚点、专家角色、更新历史都只存在聊天上下文里，后面很难做真正的长期记忆和跨版本比对。

所以要把它们做成显式对象和数据库字段。

## 5. 我建议吸收的版本

### 直接吸收

- 意图锚点
- 锚点更新记录
- 专家面板
- 场景工坊
- 一致性监察
- 沙盒模式
- 弧光追踪
- 视觉母题追踪

### 改造后吸收

- “AI 只给选项”
  - 改成默认顾问模式，而不是永久禁止扩写
- “初始化提示词”
  - 改成产品内置系统规则，不再让用户手工粘贴
- “@专家调用”
  - 改成界面上的专家按钮、命令面板或智能路由

### 先不吸收

- 过于依赖自然语言命令的交互方式
- 所有逻辑都放在同一轮对话里的实现方式

## 6. 吸收后的产品形态

如果把它并入我们现在的路线，第一版产品会更像这样：

1. 用户先建立意图锚点
2. 系统把锚点写入故事圣经
3. 用户在不同页面调用不同专家
4. 专家只读取允许的对象和约束
5. 规则引擎持续做一致性检查
6. 用户需要发散时可开沙盒模式
7. 发散结束后系统自动回归主锚点并重新扫描

## 7. 这对当前项目有什么直接影响

我已经把这份参考稿里的关键思想并入当前规格，主要体现在：

- 第一版规格里新增了“意图锚点”页面和“专家面板”
- 故事圣经规格里新增了 `IntentAnchor` 和 `AnchorRevision`
- 规则定义里新增了“弧光追踪”和“视觉母题追踪”
- 机器样例里也补了锚点对象和对应规则
