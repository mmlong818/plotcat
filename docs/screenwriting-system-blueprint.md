# 编剧系统蓝图

## 1. 项目目标

本项目的目标不是做一个“会写字的模型”，而是做一个接近专业编剧工作流的系统。

它需要同时具备四类能力：

1. 理解人心：能抓住角色欲望、缺陷、创伤、关系和情感变化。
2. 组织故事：能把主题、冲突、反转、伏笔和回收组织成稳定结构。
3. 保持自洽：能跨长文本记住人物状态、世界规则、时间线和因果链。
4. 面向拍摄：知道剧本不是小说，最终要进入开发、排练、制作和剪辑流程。

这里先做一个默认假设：

- 目标用户是认真写影视剧本的人，而不是只想随手生成短文案的人。
- 第一版优先支持电影长片和剧集试播集的开发流程。
- 产品定位是“编剧工作台”，不是“替代人类编剧的黑盒子”。

## 2. 人类编剧最强的地方，系统要怎样学

你已经指出了关键点：同理心、脑洞、超长逻辑自洽、桥段包装、影视制作经验。

把这些能力翻成产品语言，就是：

- 同理心：系统必须能从角色内部视角看待行为，而不是只会排列事件。
- 脑洞：系统不能只给模板答案，需要提供多种出路、反常规选择和类型混搭。
- 长程自洽：系统必须有结构化记忆，不能只靠一次对话窗口。
- 桥段能力：系统要会识别类型承诺、观众预期、反转时机和节奏设计。
- 制作意识：系统给出的方案要考虑场景规模、角色数量、视觉表达和可拍性。

所以这个项目的底层原则应该是：

1. 先拆解，再生成。
2. 先保存结构化事实，再写台词和场景。
3. 先评审，再扩写。
4. 让 AI 分角色协作，而不是让一个模型从头写到尾。

## 3. 方法论地图

### 3.1 宏观结构方法

这类方法解决“故事整体骨架怎么走”。

#### 三幕式

最稳定的通用骨架仍然是三段：

- 建立人物与世界
- 进入冲突并升级
- 做出关键选择并完成结果

它的价值不在“老”，而在于它是很多其他方法的共同底层。

#### 英雄之旅

Joseph Campbell 基金会对英雄之旅的总结是“分离、试炼、归来”这一核结构。它更适合处理“人物被迫离开熟悉世界，经历变化，再带着新认知回归”的故事。

对应用的意义：

- 适合成长型、冒险型、类型化较强的故事。
- 不应该当作所有故事的唯一模板。
- 更适合做“原型提示器”，不适合做硬性约束。

#### Save the Cat 15 Beat

Save the Cat 官方材料明确给出 15 个 beats，包括 Opening Image、Theme Stated、Catalyst、Midpoint、All Is Lost、Finale、Final Image。

对应用的意义：

- 很适合做面向创作者的“节奏面板”。
- 容易转成大纲检查器和缺口提醒器。
- 适合商业类型片、入门创作和改稿阶段。

#### Dan Harmon Story Circle

Story Circle 把人物变化压缩成一个循环：进入、追求、适应、得到、付出代价、返回、改变。

对应用的意义：

- 特别适合单集剧情、单人物弧线、短篇和剧集分集故事。
- 很适合用在“这一集到底让角色变了什么”这种检查上。

#### John Truby 7 Stages / 22 Building Blocks

Truby 官方课程强调故事的 7 个关键阶段，也强调 premise、character、theme、plot、scene weave、rewrite 等完整写作流程；他的软件 Blockbuster 还把 22 个 building blocks、角色网、Scene List、Rewrite 作为核心界面。

对应用的意义：

- 它最适合变成系统骨架，因为它不是只看结构，还看人物、主题、对手、场景顺序和改稿。
- 适合做成“故事圣经 -> 大纲 -> 场景 -> 重写”的主流程。

### 3.2 人物与主题方法

这类方法解决“为什么这个人必须经历这个故事”。

#### McKee 的人物观

McKee 官方课程强调：人物真正的性格不是表面设定，而是在选择、风险和困境里被揭示出来。

对应用的意义：

- 人物卡不能只存年龄、职业、口头禅。
- 必须存欲望、隐藏自我、两难选择、恐惧、价值观冲突。
- 每个重要场景都要能回答：“这个选择揭示了人物什么？”

#### Truby 的欲望、需求、对手、计划、自我揭示

Truby 的优势在于把“人物成长”和“情节推进”绑在一起，而不是分开处理。

对应用的意义：

- 系统中的每个主角都应该同时拥有：
  - 外部欲望
  - 内部需求
  - 心理缺陷
  - 道德缺陷
  - 对手
  - 行动计划
  - 自我揭示

#### 角色网

优秀编剧很少孤立地写单个人物，而是用人物之间的镜像、对照、联盟、背叛来制造戏剧。

对应用的意义：

- 角色不应该只是列表，而应该是关系图。
- 关系图要记录：亲密程度、利益冲突、信息不对称、情感债务、历史事件。

### 3.3 场景层方法

这类方法解决“单个场景为什么成立”。

一个能拍、能看、能剪的场景，至少要具备：

- 场景目标：这一场谁想得到什么
- 阻力：谁或什么在阻止
- 策略：人物如何尝试
- 转折：这一场前后发生了什么变化
- 余波：这一场把下一场逼向哪里

系统在场景层要特别检查：

1. 这场是否推动了情节
2. 这场是否暴露了人物
3. 这场是否提供了新的信息或新的风险
4. 这场是否只是重复前一场
5. 这场是否具备视觉表达，而不是只能靠解释

### 3.4 制作层方法

这类方法解决“这个剧本能不能顺利变成影视作品”。

#### 格式不是全部，但必须专业

奥斯卡 Nicholl 的资源页明确指出：行业没有绝对唯一标准，但专业剧本会整体接近标准格式。

对应用的意义：

- 排版不是创作核心，但必须作为最后一层稳定输出。
- 应用不能把格式错误当作创意能力。
- 更重要的是避免明显的阅读阻力，例如过长动作段落、非标准标记、混乱页眉页脚。

#### 影视开发需要制作意识

ScreenSkills 对 script editor 的说明强调，优秀剧本开发不仅要懂文本，还要理解把剧本变成影视作品时的实际与后勤因素。

对应用的意义：

- 系统要能标记高成本场景、群演密度、地点切换频率、动作难度、特殊道具依赖。
- 系统要支持“创作好”和“可拍”之间的平衡，而不是只追求纸面华丽。

#### 读台词和读场

ScreenSkills 的课程说明还强调，演员带读、同伴讨论、制作方视角会暴露节奏、紧张感和盲点。

对应用的意义：

- 后续应用很适合加入“角色朗读模拟”和“演员视角反馈”。
- 这能帮助发现对白拗口、情绪跳变、信息量失衡等问题。

## 4. 把方法论转成系统规则

最关键的一步，是区分三类规则。

### 4.1 硬规则

这类规则如果出错，剧本通常会直接失真或失控。

- 人物身份不能前后冲突
- 时间线不能自相矛盾
- 世界规则不能随意变化
- 因果链不能断裂
- 伏笔与兑现关系要可追踪
- 场景中的知识状态要一致
- 重要角色的动机变化必须有触发原因
- 输出格式必须可读、可导出、可共享

### 4.2 软规则

这类规则不是铁律，但大量优秀作品会在某种程度上满足它们。

- 主题应尽早被建立
- 主角应尽早形成清晰欲望
- 中段应有结构性变化，而不是平推
- 对手应推动主角暴露真实自我
- 结尾应是前面选择的结果，不是天降解决
- 支线应服务主线、人物或主题，而不是单独飘着

### 4.3 创意规则

这类规则不用于扣分，而用于启发突破。

- 有没有更反常规但更合理的选择
- 这个桥段是不是太像同类型旧片
- 是否能把外部冲突改成关系冲突
- 是否能把解释性对白改成动作和行为
- 是否能把高潮从“赢没赢”升级成“成了怎样的人”

## 5. 应用应该具备的核心模块

### 5.1 Premise Lab

作用：把模糊灵感压成可工作的故事种子。

输入：

- 一句话点子
- 类型
- 主题
- 想做出的情绪体验

输出：

- logline
- premise
- 类型承诺
- 核心冲突
- 风格方向

### 5.2 Character Web

作用：建立角色网络，而不是单个角色档案。

输出至少应包含：

- 外部欲望
- 内部需求
- 缺陷与创伤
- 价值观
- 关系张力
- 隐藏信息
- 变化弧线

### 5.3 Story Bible

作用：保存长期稳定的世界事实。

应包含：

- 世界设定
- 时间线
- 阵营与关系
- 世界规则
- 不能违反的前提
- 伏笔与待回收项
- 视觉母题

### 5.4 Plot Lab

作用：在多种方法论之间切换视图。

建议支持的视图：

- 三幕式视图
- Save the Cat 视图
- Story Circle 视图
- Truby 视图
- 自定义 beat 视图

重点不是逼用户选一种，而是允许同一故事被多种镜头审视。

### 5.5 Scene Room

作用：逐场编写和评审。

每场都应有结构化卡片：

- POV 角色
- 场景目标
- 阻力
- 关键动作
- 情绪变化
- 信息增量
- 与上一场、下一场的因果关系
- 预计制作复杂度

### 5.6 Continuity and Logic Engine

作用：专门抓长剧本最容易崩的地方。

应检查：

- 人物记忆是否一致
- 物件状态是否一致
- 时间间隔是否合理
- 角色是否知道自己不该知道的信息
- 世界规则是否被违反
- 伏笔是否长期悬空

### 5.7 Rewrite Room

作用：把改稿变成显式流程，而不是“再来一版”。

建议把改稿拆成：

1. 结构改稿
2. 人物改稿
3. 场景改稿
4. 对白改稿
5. 格式与可拍性改稿

### 5.8 Production Lens

作用：在创作早期就给制作提醒。

可输出：

- 高成本场景清单
- 高频地点统计
- 高密度角色场景
- 夜戏与外景占比
- 动作、特效、群演标记

## 6. 为什么不能做成“一键生成整部剧本”

最新研究基本都在说明同一件事：直接一次性生成完整剧本，通常会在深层结构上失稳。

### 已有研究给出的启发

- HoLLMwood 证明：让模型分成 Writer、Editor、Actor 等角色协作，整体质量比单一写法更好。
- Beyond Direct Generation 认为：剧本生成失败的重要原因，是把“创意叙事”和“格式排版”硬塞给同一个阶段；他们提出先写叙事，再转成专业剧本格式。
- DuoDrama 说明：编剧在改稿时需要的是“角色内部视角”和“整体故事外部视角”同时存在。
- Constella 说明：多代理方式很适合辅助角色关系网络，而不仅是单角色扩写。
- STAGE 说明：要想真正理解剧本，需要知识图谱、长文本问答、场景摘要和角色扮演能力。
- DramaBench 给出了 6 个适合做评测的维度：格式、叙事效率、角色一致性、情感深度、逻辑一致性、冲突处理。
- Finding Flawed Fictions 说明：LLM 在长故事里很容易制造 plot hole，甚至在总结和生成时会显著放大问题。

结论很明确：

这个应用的核心竞争力，不是“写得快”，而是“在长程创作里不失真”。

## 7. 推荐的系统架构

### 7.1 工作流

建议使用 7 步工作流：

1. 灵感转 premise
2. premise 转角色网与主题
3. 角色网转 story bible
4. story bible 转 beat outline
5. beat outline 转 scene cards
6. scene cards 转 screenplay draft
7. screenplay draft 进入多轮评审与改稿

### 7.2 代理分工

可以把系统拆成这些角色：

- Showrunner：守住主题、类型和总方向
- Story Architect：负责整体结构和 beats
- Character Psychologist：负责动机、创伤、关系和情感逻辑
- Scene Writer：负责单场推进和对白
- Continuity Editor：负责事实一致性和伏笔回收
- Production Editor：负责可拍性和成本提醒
- Audience Simulator：模拟不同观众视角的感受

### 7.3 结构化存储

后端不要只存文本，要存结构。

至少需要这些对象：

- Project
- Theme
- Genre
- Character
- Relationship
- WorldRule
- TimelineEvent
- Beat
- SceneCard
- SetupPayoff
- ProductionConstraint
- ReviewNote

## 8. 第一版应用建议做什么

### 最快路线

做一个“故事开发助手”：

- 输入一句话点子
- 输出 premise、角色网、三幕大纲、场景卡
- 自动做逻辑检查和伏笔追踪

优点：

- 见效快
- 最容易验证产品价值
- 技术风险最低

### 最稳路线

做一个“故事圣经 + 改稿工作台”：

- 不追求直接写完整剧本
- 先把世界、角色、时间线、关系、伏笔管住
- 支持逐场写作和逐轮评审

优点：

- 最接近专业编剧真实痛点
- 最能拉开和普通聊天机器人的差距

### 最完整路线

做一个“全流程编剧系统”：

- 从 logline 到大纲、场景、对白、排版、可拍性检查全部覆盖

优点：

- 上限最高

代价：

- 产品复杂度高
- 需要更完整的结构化数据与评测体系

## 9. 我建议的默认路径

如果现在就开始做，我建议先走“最稳路线”。

也就是先做下面这 4 个功能：

1. 故事圣经
2. 剧情大纲工作台
3. 场景卡与连续性检查
4. 改稿反馈系统

原因很简单：

- 它最接近人类编剧真正花时间的地方
- 它最能体现你强调的“超长逻辑自洽”
- 它不会过早掉进“直接生成长剧本但质量不稳”的陷阱

## 10. 成功标准

这个项目是否成功，不该只看“能不能生成 120 页”。

更应该看：

- 用户是否更快找到一个可写的 premise
- 用户是否更容易看出角色弧线问题
- 用户是否能更早发现逻辑漏洞
- 用户是否能减少大改次数
- 用户是否愿意把它用于第二个、第三个项目

## 11. 仍需你拍板的关键选择

后续继续推进前，最值得尽快定下来的有四件事：

1. 第一版主打电影长片，还是剧集 pilot
2. 第一版服务个人编剧，还是小团队开发
3. 第一版是偏“共创生成”，还是偏“评审改稿”
4. 第一版先做中文创作，还是中英双语
