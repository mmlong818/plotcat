# 编剧工作台配色系统规范

## 1. 目标

这套规范解决两个问题：

- 所有页面都要有自己的识别气质，但不能一页一个审美体系。
- 画面必须先让人看懂层级，再让人感受到风格。

因此配色系统要满足：

- 不同页面使用不同色相。
- 所有页面使用同一套明度梯子。
- 卡片尽量保持中性，不让卡片自己承担过多语义。
- 颜色不能同时表达“页面归属”“对象归属”“状态风险”三件事。

## 2. 配色原则

### 原则 1：色相归页面

每个页面可以有独立色相，但只允许使用一组主色家族。

- 结构页：陶土灰
- 剧情板：板岩蓝灰
- 角色台：苔藓灰绿
- 类型约束：烟金灰
- 锁定层：石墨灰褐
- 场景页：酒红灰棕

### 原则 2：明度归层级

所有页面必须共用同一套亮度关系。

从暗到亮固定为：

1. 页面底
2. 模块底
3. 区域底
4. 侧栏底
5. 卡片底
6. 输入框底

用户换页时，应该感受到“页面换气质了”，而不是“层级规则换了”。

### 原则 3：对象色只做识别

角色色、剧情线色、方案轨色，不直接铺满整张卡片，只用于：

- 标签
- 轨道底色
- 小圆点
- 侧边条
- 关系线
- 节点标记

### 原则 4：状态色只做状态

风险、锁定、待确认、废弃，统一走状态色，不与页面色或对象色混用。

推荐状态色：

- 已锁定：深石墨蓝灰
- 待确认：烟金灰
- 风险：铁锈灰红
- 废弃：冷灰

## 3. 明度梯子

下面不是唯一数值，但明度关系必须固定。

| 层级 | 用途 | 建议明度感觉 | 说明 |
| --- | --- | --- | --- |
| L1 | 页面底 | 最暗 | 用来承托整页，避免漂浮感 |
| L2 | 模块底 | 比页面亮一档 | 用来区分当前工作模块 |
| L3 | 区域底 | 中间层 | 用来区分主工作区和二级工作区 |
| L4 | 侧栏底 | 比区域略暗或同级偏深 | 用来强调“附属但重要” |
| L5 | 卡片底 | 接近高亮 | 用来承载可操作对象 |
| L6 | 输入框底 | 全局最亮 | 保证可编辑区域最清楚 |

额外固定两层：

- `border-soft`：软边框，用于同层内容之间
- `border-strong`：硬边框，用于模块与工作区之间

文字固定两层：

- `text-primary`：主文字
- `text-secondary`：辅助文字

## 4. 页面色系矩阵

### 4.1 结构页

- 页面色相：陶土灰
- 适合表达：骨架、幕、节拍、必要节点
- 应用位置：
  - 整页模块底
  - 幕区背景
  - 结构标题条

### 4.2 剧情板

- 页面色相：板岩蓝灰
- 适合表达：排序、推演、方案并排
- 应用位置：
  - 剧情板模块底
  - 方案轨 / 主线轨 / 支线轨区域底
  - 拖动时的落点高亮

### 4.3 角色台

- 页面色相：苔藓灰绿
- 适合表达：人物、阵营、关系、成长
- 应用位置：
  - 角色档案区
  - 关系区
  - 人物标签

### 4.4 类型约束

- 页面色相：烟金灰
- 适合表达：约束、类型承诺、桥段覆盖
- 应用位置：
  - 类型模块底
  - 必备桥段区
  - 风格承诺区

### 4.5 锁定层

- 页面色相：石墨灰褐
- 适合表达：沉淀、审查、版本确认
- 应用位置：
  - 锁定区
  - 差异比对区
  - 投影结果区

### 4.6 场景页

- 页面色相：酒红灰棕
- 适合表达：执行、切场、文字化
- 应用位置：
  - 场景列表区
  - 场景编辑区
  - 节奏拆分区

## 5. 区域色与对象色的分工

## 5.1 页面色

页面色只回答一个问题：

- “我现在在哪一页”

不要让页面色去表示状态、优先级或人物归属。

## 5.2 区域色

区域色回答：

- “这块区域现在归谁管理”

例如：

- 结构视图里，幕区是彩色区域
- 排演视图里，轨道是彩色区域
- 角色台里，阵营或角色组可以是彩色区域

## 5.3 对象色

对象色回答：

- “这是哪个角色 / 哪条线 / 哪个方案”

对象色只用于轻量标记，不用来铺整张卡片底色。

## 5.4 状态色

状态色回答：

- “它现在安全吗”

状态色只用于：

- 锁定
- 风险
- 冲突
- 废弃

## 6. 角色色规则

角色不建议从第一版开始就“人人一色”。更稳的是三级体系。

### 一级：重要角色独立色

适用对象：

- 主角
- 核心对手
- 第一梯队关键人物

这些角色可以有自己的识别色，但只出现在：

- 人名标签
- 头像点
- 关系线
- 被剧情卡引用时的标记

### 二级：次要角色共用色

适用对象：

- 同阵营角色
- 同功能角色
- 次要但常用角色

建议按阵营或功能共用色，降低杂乱度。

### 三级：普通角色中性灰

适用对象：

- 一次性角色
- 边缘功能角色
- 还没被确认的重要度角色

## 7. 剧情板色规则

剧情板要区分两个视图。

### 7.1 结构视图

颜色归属给“幕”。

- 幕区是底色块
- 节点用更浅的小块或分隔条
- 剧情卡保持中性
- 轨道只用标签和细线区分

适合：

- 看节奏
- 看幕内密度
- 看节点覆盖

### 7.2 排演视图

颜色归属给“轨道”。

- 正式主线是一条底色轨
- 支线是一条底色轨
- 未定义是一条中性轨
- 方案轨 A/B/C 各有独立底色轨
- 幕只作为顶部栏目和轻分隔

适合：

- 拖动排序
- 方案比较
- 主支线关系判断

### 7.3 卡片颜色规则

剧情卡自身尽量中性：

- 默认卡：浅灰白
- 当前选中：边框加深 + 左侧标记
- 已锁定：状态徽标，不改大底色
- 风险卡：状态标识，不改整卡底色

## 8. 剧情板轨道底色建议

轨道底色不是鲜色，而是高级灰偏色。

| 轨道 | 色彩方向 | 用途 |
| --- | --- | --- |
| 正式主线 | 深板岩蓝灰 | 当前正式故事走向 |
| 支线 | 苔藓灰绿 | 人物支线、副冲突 |
| 未定义 | 冷灰 | 还未归类的剧情卡 |
| 方案轨 A | 灰陶土 | 第一种解法 |
| 方案轨 B | 灰蓝 | 第二种解法 |
| 方案轨 C | 灰金 | 第三种解法 |

## 9. CSS 变量建议

建议后续用设计令牌，而不是页面里写死颜色。

### 9.1 全局层级令牌

- `--surface-page`
- `--surface-module`
- `--surface-region`
- `--surface-side`
- `--surface-card`
- `--surface-input`
- `--border-soft`
- `--border-strong`
- `--text-primary`
- `--text-secondary`

### 9.2 页面色系令牌

- `--page-structure-hue`
- `--page-plots-hue`
- `--page-characters-hue`
- `--page-genres-hue`
- `--page-locks-hue`
- `--page-scenes-hue`

### 9.3 对象色令牌

- `--role-primary-1`
- `--role-primary-2`
- `--role-group-a`
- `--role-group-b`
- `--lane-main`
- `--lane-sub`
- `--lane-undefined`
- `--lane-scenario-a`
- `--lane-scenario-b`
- `--lane-scenario-c`

### 9.4 状态色令牌

- `--state-locked`
- `--state-review`
- `--state-risk`
- `--state-discarded`

## 10. 执行顺序

推荐按这个顺序落地：

1. 先统一全局明度梯子
2. 再统一每页主色家族
3. 再加区域底色
4. 再加对象色标签
5. 最后再补状态色和交互高亮

不要一开始就给所有对象上色。

## 11. 第一版不做什么

为了避免画面失控，第一版明确不做：

- 每个普通角色独立配色
- 每张剧情卡独立底色
- 页面内同时让“幕”和“轨道”都铺重色底
- 用颜色单独表达过多信息

第一版要优先确保：

- 用户能一眼看懂页面
- 用户能一眼区分区域
- 用户能在不看文字的情况下感受到当前在哪一页
